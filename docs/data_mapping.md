# Source-to-Flowstock field mapping

The table describes the independent offline fixture and the shared grocery generator. Identifier origins become `real` for imported source snapshots; the per-package `schema.json` and row provenance record that distinction. Original normalized daily/hourly source fields remain unchanged in local curated Parquet. No semantic source product names, prices, costs or unit counts are inferred.

## Source Parquet and model outputs

Original source columns and observed types are recorded in `freshretailnet_manifest.json`. `city_id`, `store_id`, `product_id` and all hierarchy IDs are real encoded identifiers. `dt`, `sale_amount`, `hours_sale`, `stock_hour6_22_cnt`, `hours_stock_status`, `discount`, `holiday_flag`, `activity_flag`, `precpt`, `avg_temperature`, `avg_humidity`, `avg_wind_level` are preserved source fields. Their units are defined by the publisher; sales are normalized amounts, not literal units. Schema/null/duplicate/negative/identifier and hourly-structure checks run before selection.

Additional forecast CSV fields for prepared models: `model_version` (derived artifact ID), `model_forecast` (derived 14-day prediction × synthetic scale 10), `model_normalized` (original normalized prediction), `lower`/`upper` (validation-calibrated interval × scale 10), `baseline` (past 14-day average × horizon × scale), `fallback` (inference availability), `quality` (precision indicator), `signals` (global historical validation signals), `ranking_score` (proxy challenger output). All are derived; none represent observed commercial outcomes.

## Recommendations and decisions

The authoritative recommendation contract is the typed `Run` and `WorkingRow` in `src/lib/server/runs.ts` and `src/lib/domain/types.ts`, persisted as JSON, with one plan per run. Existing identifiers and operational fields inherit the CSV provenance above. Forecast fields retain derived origin; proposed/final quantities are synthetic operational quantities; expected margin/revenue and normalized objective contributions are simulated. New fields: `id`/`plan_id` (generated immutable IDs), `config` (versioned administrative settings), `status`/`approval_state` (workflow state), `created_at`/`updated_at` (ISO timestamps), `revision` (optimistic edit version), `source_hash` and `inventory_hash` (derived integrity hashes), `summary` (simulated objective, service, reconciliation and shortfall). `constraintAdjustments` and `constraintWarnings` are deterministic reasons, not LLM output.

Decision audit entries have `id`, `timestamp`, `action`, `actor` and `details`; details record run/model ID, old/system quantity, final quantity, comment, state changes and numeric gates as applicable. These are actual local planner/test actions, never claimed as publisher historical allocation data. API request schemas and required/null policies are in `openapi.json`; quantities must be nonnegative integers, override comments and decision reasons must be nonempty, and unknown keys are rejected.
